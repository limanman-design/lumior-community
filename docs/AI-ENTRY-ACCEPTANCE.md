# AI 统一入口与验收规范

2026-10-24，按用户要求建立。适用于普通研究、PDF 翻译、四个 MBA skill 及后续新增 AI 功能。

## 接入方式

本机 API 保留各自业务路径，模型调用统一通过 `lib/ai-runtime.ts`：先 `resolveAiAccess` 决定当前体验/个人 Key 来源和具体模型，再 `createAiTask` 取得 `call` 与 `finish`。在 `finally` 中结束任务。新增对话、助手、工具默认使用 `research` 分类，不需要增加邀请码权益；翻译分类只用于区分任务。

MBA 固定 Kimi K3.1 Pro（`kimi:kimi-k3.1-pro`），原版四个 Skill 直接运行，思考强度 high，不再额外调用范围检查模型。同一轮工具、校验、修复仍属于同一个任务。全局默认模型不覆盖 MBA，普通研究与翻译保持自己的模型策略。供应商更换须取得对应资料处理同意，原有 DeepSeek 同意不能代替 Kimi 同意。

`lib/thesis/model-call.ts` 是个人 Key 对照评测的兼容适配器，底层仍通过统一运行层；产品请求必须使用任务生命周期。不得在新功能里直接导入供应商调用或复制体验/个人 Key 分支。供应商目录查询、DOI 网页查证、本地 PDF 提取不属于收费模型生成调用。

## 必须验证的行为

| 编号 | 验收要求 | 本次证据 |
| --- | --- | --- |
| A1 | 只有已领取的体验凭据、没有任何个人 Key，可以普通问答、翻译、定题、读文献、综述、开题 | `ai-runtime.test.mjs` 经真实网关核心和账本，模拟模型回执 |
| A2 | 旧激活码可继续领取、旧凭据沿用；不重置余额、到期时间，不另建 MBA 用户或资格 | `trial-gateway.test.mjs` 原领取幂等测试；统一入口测试使用旧格式已领取用户 |
| A3 | 主回答及规划、核对、校验、修复全部进入同一任务并扣同一余额 | 普通研究计划/回答/复核，MBA high 指导及工具续跑，翻译多批测试 |
| A4 | 个人 Key 模式沿用原模型调用；体验失败不能偷偷回退个人 Key | `ai-trial`、`ai-providers`、`thesis-providers`、`pdf-translation` 测试 |
| A5 | 额度不足、到期、撤销时阻止调用并显示原因，配置状态也反映不可用 | 统一入口及网关测试 |
| A6 | 所有功能共享个人/全局并发、日任务数和每轮调用上限；不得每一步新建任务绕开 | 网关限制测试；MBA 第 7 次调用被阻止，同一会话下一轮可接着做 |
| A7 | 取消、断连、超时、供应商异常均清理任务；取消后清理请求不复用已中止信号 | 统一入口取消测试、体验任务/翻译取消测试 |
| A8 | 上游费用未知时保留预留款和安全租约，不自动退款或自动重发 | 网关账本、取消测试 |
| A9 | 完整 skill、工具定义和材料能经过真实容量校验；超限明确报错，不悄悄截断 | 四个完整 MBA prompt 经网关；大输入完整性与超限测试 |
| A10 | 扩容时按实际请求的保守输入上界预留，不能只扩大 HTTP 限制；老调用按原上界结算 | 网关费用边界及扩容结算测试 |
| A11 | 项目资料、对话、用户编辑与待采纳成果沿用既有保存规则；达到调用上限后可续跑 | MBA 续跑、thesis-board、thesis-runtime 回归 |
| A12 | 前端不见个人 Key、服务端 Key 或体验 token；跨来源请求被拒绝 | 本机 API、网关、桌面凭据测试 |
| A13 | 生产构建通过；能力查询向后兼容，发布时先更新网关再更新客户端，并独立报告实际发布状态 | 类型检查、lint、生产构建；真实 workerd 协议测试 |

每次按变更范围执行相关项，不为低影响文案反复全量验证。涉及新增入口、授权、额度或协议时，A1–A10 必须重新核对。不得用“个人 Key 调得通”代替体验模式验收，也不得把模拟回答说成线上实测。真实模型质量另行评测。

## 容量与兼容边界

新网关按账号响应公开 `maxRequestBytes=240000`、`maxMessages=256`。客户端缺省仍用旧网关的 30000 字节、64 条消息，因此不能先发新客户端再期待旧网关支持长 MBA prompt。所有功能共用这些限制，没有新增“论文权限”。

每次外呼使用 `max(32000, 完整模型请求 JSON 的 UTF-8 字节数 + 8000)` 作为保守输入 token 上界，记录到本次调用；按此上界与 8192 输出 token 预留费用，收到可靠 usage 后按实际量结算。服务端限制输入上界不超过 256000；历史调用没有新字段时仍按 32000 验证。实际 token 用量或账单超过已预留边界时进入待核对，不直接释放预留。

每轮仍最多 6 次模型调用、20 分钟；个人/全局余额、并发、每日任务数不增加。文献或会话仍可能超过容量；提示缩小范围或改用个人 Key，不声称无限全文阅读。MBA 达到调用次数上限会保留本轮经过校验的状态，下一轮可在同画板继续。

## 社区检查与私有服务检查

公开候选保留统一入口规范与模拟协议测试。真实官方网关、账本与部署运行时的验收在私有服务工程执行。每次修改分别报告模拟请求、真实调用、未测项和发布状态；历史发行记录不随候选源码提供。
